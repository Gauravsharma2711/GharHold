# ADR-002: Pure Domain State Machines, Owner Role Demo Seam, and Controllable Simulated Remote Fault Boundary

## Status
Accepted

## Context
A proptech application managing scarce physical inventory requires strict state machines to prevent illegal operations (such as approving an already-declined request without an explanation, holding a property with a token before the viewing is approved, or allowing renters to perform owner-only operations). Additionally, judging and verifying offline recovery and stale conflict handling on a single device requires controllable, deterministic fault injection and role simulation without deploying complex hosted infrastructure or managing separate login accounts.

## Decision
1. **Pure Dart Domain Layer**: All business rules (`ProptechBusinessRules`), data models (`PropertyListing`, `ViewingRequest`, `AuditEvent`, `CostBreakdown`), and ports (`Clock`, `IdGenerator`, `RemoteService`, `ProptechRepository`) are isolated in `lib/domain/`. The layer has zero imports of Flutter, Drift, SQLite, platform, or network packages, enforced by automated compiler/import tests (`test/domain/domain_purity_test.dart`).
2. **Deterministic State Transitions**:
   - Listings: `AVAILABLE` $\to$ `VIEWING_REQUESTED` $\to$ `TOKEN_LOCKED` $\to$ `UNAVAILABLE`.
   - Requests: `REQUESTED` $\to$ `APPROVED` $\to$ `TOKEN_REQUESTED` $\to$ `TOKEN_CONFIRMED`.
   - Invariant: `DECLINED` requests cannot jump directly to `APPROVED`. They must be explicitly reopened with a non-empty trimmed reason (`REOPENED`), and reopening requires the listing to be available with no other active request.
   - Hold with token is permitted only after a viewing request has been `APPROVED`.
3. **Role Switcher as Demo View Seam**: A persistent Architecture Inspection Bar allows toggling between Renter and Owner demo roles. This is explicitly a presentation-layer demonstration seam, not authentication or security enforcement. Domain rules reject non-owner actions if called with non-owner roles.
4. **Controllable Simulated Remote Service**: `SimulatedRemoteService` implements the `RemoteService` port with in-memory `FaultConfig`:
   - `normal`: Simulates 500ms network latency and validates optimistic listing versions.
   - `dropNetwork`: Throws `NetworkException` after local persistence, proving safe local retry.
   - `staleConflict`: A one-shot fault that advances the simulated server listing to version 2 (`UNAVAILABLE`) and throws `StaleVersionConflict`, proving optimistic concurrency reconciliation.
   - Clear disclosure: Persistent Inspection Bar displays a prominent **SIMULATION** badge to ensure honest presentation.
5. **Mobile Application Observability via Measure.sh**: Mobile health, ANRs, Flutter crash reporting, screen navigation, and performance spans are integrated using the `ObservabilityService` abstraction backed by Measure.sh (`MeasureObservabilityService`), maintaining strict separation from GharHold's internal SQLite audit sink (`DiagnosticSink`). All sensitive attributes and notes are filtered or masked on-device (`MsrMask`), and telemetry failures are architected to never affect business transactions.

## Alternatives Considered
- **Placing Business Rules in Flutter UI / State Notifiers**: Discarded to prevent logic duplication, UI coupling, and difficult unit testing.
- **Real Backend / Cloud Infrastructure (AWS/Firebase/Supabase)**: Discarded per project instructions; introduces network flakiness during hackathon demos, setup latency, and credential dependencies.
- **Two Separate Mobile Apps or User Login Accounts**: Discarded because hackathon judging requires rapid 5-minute role switching between Renter and Owner perspectives on a single device.

## Consequences & Limitations
- **Consequences**: Business rules are 100% deterministic, testable in milliseconds, and completely decoupled from UI widgets or database tables. Fault modes are reproducible on demand during judging.
- **Limitations**: The role switcher is a demo convenience. Production multi-tenant deployments will require cryptographic user authentication and authorization gateways.
